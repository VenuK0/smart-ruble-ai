# SmartRubleAI — от исследовательского прототипа к v1.0

**Версионирование — внутренний план команды, а не обещание готовности к определённой дате.**

## Что означает «готовый продукт»

В версии **v1.0** мы предполагаем завершённое устанавливаемое веб-приложение
**для ограниченного пилота**: оператор может создать смету, провести
демонстрационную проверку чека, передать спорную позицию уполномоченному
сотруднику, получить результат, отчёт и воспроизводимый журнал.

**v1.0 не будет означать:**
- осуществление реальных операций с цифровым рублём;
- подключение к Банку России, банкам, реальным грантам или платёжной инфраструктуре;
- подтверждение финансовой эффективности или точности ИИ на реальных данных;
- банковскую сертификацию или соответствие требованиям промышленной
  эксплуатации без отдельной оценки и договорённостей.

**Главный принцип:** номер выпуска присваивается только после прохождения
контрольного списка; функция, которая лишь нарисована в интерфейсе, не считается реализованной.

| Этап | Результат | Критерий приёмки |
| --- | --- | --- |

| v0.7 — доступ | Учётные записи, роли (администратор, контролёр, наблюдатель), разграничение грантов, защитные ограничения API | Неавторизованные запросы отклоняются; действия по чужой смете запрещены; журнал фиксирует идентификатор инициатора; проведена проверка безопасности |

| v0.9 — релиз-кандидат | Функциональная/нагрузочная приёмка, UX на телефоне, документация установки, наблюдаемость и эксплуатационный план | Нет блокирующих дефектов; восстановление и доступность проверены, нет известных критических уязвимостей |
| v1.0 — пилотная версия | Устанавливаемый ограниченный продукт с разъяснёнными пределами использования | Пройдены все обязательные проверки ниже и подписан акт приёмки команды |

## Обязательные блокирующие требования для v1.0

- [ ] Все состояния смет, чеков и ручных решений переживают перезапуск сервера.
- [ ] Обновление лимита и запись в журнал — одна транзакция; при сбое откатываются вместе.
- [ ] При параллельной отправке одного чека/решения не появляется повторное списание.
- [ ] Всякий изменяющий запрос требует аутентификации и проверки полномочий.
- [ ] Чужие сметы и данные недоступны другому пользователю.
- [ ] В журнале есть время, тип операции и проверяемый субъект действия;
      сохранение исходных чеков и истории изменений протестировано.
- [ ] Проверены восстановление из резервной копии, ограничения доступа,
      основные угрозы, управление секретами и обновление приложения.
- [ ] Пользователь может пройти создание сметы → классификацию → REVIEW →
      решение человека → отчёт в браузере без ручных SQL или API-команд.
- [ ] У ИИ указаны точность, ошибки на отложенной выборке, доля ручной проверки,
      дата и способ обучения; на реальных данных без отдельной валидации — нет заявлений.
- [ ] Любые финансовые показатели явно разделены на измеренные и сценарные.
- [ ] Есть документация по установке, эксплуатации, лимитам и ограничениям.
- [ ] Проверка компьютера и мобильных экранов пройдена; выпуск подписан командой.

## Ближайший приоритет: форум 2026

**Не расширять область в ущерб демонстрации.** Перед защитой:
1. проверить объединённый сценарий v0.5 на Honor;
2. убедиться, что воспроизводимые исследовательские результаты совпадают с CI;
3. сохранить офлайн PDF презентации, CSV, отчёт, скриншоты и видео;
4. отрепетировать выступление на 5 минут, отдельно проговорив ограничения;
5. не обновлять отправленную заявку без отдельной договорённости с организаторами.
