# Ограничения безопасности SmartRubleAI v0.2

Система — исследовательская симуляция. Не подходит для реальных платежей и хранения персональных финансовых данных.

## Что реализовано

- Положительные конечные суммы, ограничения на размер чека и строгая проверка API.
- Защита от повторной обработки того же ID чека в одном процессе.
- Синхронизация операций одного контракта через lock в рамках одного процесса.
- Откат изменения лимитов при исключении при обработке чека.
- Цепочка SHA-256 для обнаружения изменения записи или времени в локальном журнале.
- Юнит-, интеграционные и стресс-тесты на синтетических данных.

## Что НЕ реализовано

- Аутентификация пользователей, RBAC и изоляция данных разных пользователей.
- Персистентная БД, резервное копирование, транзакции между процессами.
- Системная защита от повторов при нескольких экземплярах приложения.
- Реальная платёжная инфраструктура или смарт-контракт Банка России.
- Защита от изменения журнала злоумышленником, способным пересчитать всю цепочку: SHA-256 без внешнего доверенного якоря/подписи не дает такой гарантии.
- Независимый аудит защищенности, нагрузочные и пенетрационные испытания.
- Оценка качества на реальных данных.

## Правило запуска

Использовать локально: python -m uvicorn smartruble.api:app --app-dir src --host 127.0.0.1 --port 8000

Не открывать порт 8000 в интернет и не обрабатывать персональные данные, пока не созданы авторизация, ограничение доступа, хранилище, межпроцессная идемпотентность, наблюдаемость и политика обработки данных.

Успешные тесты не равны банковской сертификации.
