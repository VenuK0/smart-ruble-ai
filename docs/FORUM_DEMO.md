# СмартРубль AI — сценарий показа v0.3.0-dev

> Для очной демонстрации преподавателю или жюри. Это исследовательская симуляция: нет реальных платежей, интеграции с цифровым рублём, авторизации и постоянной базы данных.

## Подготовка

1. Обновить ветку **main**: в PowerShell выполнить команды ниже.
2. Убедиться, что по адресу http://127.0.0.1:8000/health возвращается status=ok и mode=simulation.
3. Открыть http://127.0.0.1:8000/app на масштабе 100%, при необходимости нажать Ctrl+F5.
4. Не перезапускать сервер во время выступления: данные смет и история находятся в оперативной памяти.
5. Не публиковать приложение на сетевом интерфейсе 0.0.0.0: в этой версии отсутствует авторизация.

    git switch main
    git pull origin main
    py -m uvicorn smartruble.api:app --app-dir src --host 127.0.0.1 --port 8000

## Последовательность показа (около 5–6 минут)

### 1. Проблема — 40 секунд

Показать «Рабочий стол». Идея: сопоставлять **отдельные позиции чека** с условиями сметы до *условного* списания средств. Продукт демонстрирует симуляцию принятия решений, а не реальные переводы.

### 2. Создать смету — 60 секунд

Открыть «Сметы и лимиты». Новый уникальный номер, например **форум-демо-2026**. В таблице по очереди выбрать категории и ввести суммы **обычными цифрами**:

| Категория | Лимит в рублях |
|---|---:|
| Расходные материалы | `50000` |
| Оборудование | `120000` |
| Услуги | `10000` |

Нажать «Добавить статью» для следующих строк. **Ни длинное тире, ни знак ₽ вводить не надо.** Можно нажать «Заполнить пример» или раскрыть необязательный «Импортировать строки», куда подходит `Материалы - 50000`.

Нажать «Создать смету». Общий лимит — **180 000 ₽**; проверить наличие трёх категорий и остатки. Если такая смета уже создана на репетиции, использовать другое имя с суффиксом.

Что реализовано: разбор статей по ключевым словам; это пока не полноценное извлечение документов языковой моделью.

### 3. Проверить два чека — 90 секунд

Перейти в «Проверка чеков» с выбранной сметой.

**Первый чек:** продавец «ООО Лаборатория», товар **резистор**, количество **2**, цена **1250,50 ₽** (в поле можно ввести `1 250,50`, без знака ₽). Предварительная сумма — **2 501 ₽**. Нажать «Проверить чек» и показать категорию, принятое решение и объяснение. Автоматическое одобрение зависит от текущей уверенности классификатора и остатка лимита.

Нажать «Новый чек».

**Второй чек:** продавец «ООО Лаборатория», товар **Лак**, количество **1**, цена **500 ₽**. Объяснить решение, которое реально показала система. Ранее для такого наименования возникала низкая уверенность, но нельзя обещать неизменный результат после переобучения.

«На проверке» — сигнал о необходимости человека; сама очередь ручного согласования пока не реализована.

### 4. Журнал и остатки — 70 секунд

Открыть «История операций», проверить две записи и индикатор целостности журнала. Найти слово **Лак**, посмотреть причины и суммы, отфильтровать по статусу и скачать CSV для Excel.

Вернуться в «Сметы и лимиты»: из разрешённого остатка вычитаются только **автоматически одобренные** позиции. Журнал основан на хэш-цепочке в памяти сервера, а не на внешнем неизменяемом реестре.

### 5. Исследование аномалий — 40 секунд

Открыть «Проверка аномалий», номер набора **3**, нажать «Выполнить анализ». Показать топ-10 и характеристики продавца: число операций, получателей, ночные операции, концентрацию и круглые суммы.

Эта выборка **отдельная и синтетическая**. Балл Isolation Forest — не вероятность мошенничества и не доказательство нарушения.

### 6. Экономическая оценка — 50 секунд

В разделе «Экономическая оценка» оставить стандартные предположения:

| Параметр | Значение |
|---|---:|
| Отчётов в год | 5 000 |
| Время вручную | 20 минут |
| Время с системой | 8 минут |
| Стоимость часа | 450 ₽ |
| Эксплуатация за год | 200 000 ₽ |
| Разработка | 1 018 000 ₽ |

Нажать «Рассчитать сценарии». Базовый **расчётный** чистый эффект — **250 000 ₽/год**, простая окупаемость — **4,07 года**. Сравнить нагрузку 60/100/140% и пятилетний график.

Это оценки по введённым предположениям, не подтверждённая экономия. Не учтены дисконтирование, инфляция, интеграция, налоги и риски.

## Ответы на возможные вопросы

- **Что делает ML?** TF–IDF символьных n-грамм + логистическая регрессия определяют категорию товара. После этого отдельные правила проверяют статью и лимит.
- **Почему статус «На проверке»?** Неуверенные решения требуют специалиста, которого в текущей симуляции ещё нет.
- **Где цифровой рубль?** Реализована концептуальная логика расходования по условиям сметы; подключения к инфраструктуре Банка России нет.
- **Есть ли доказанные результаты внедрения?** Нет реального пилота. Аномалии проверяются на синтетике; экономический эффект оценивается по заданным допущениям.
- **Что потребуется для промышленной версии?** Авторизация и роли, постоянная БД, безопасный аудит, реальные интеграции и правовая экспертиза.

## Если во время выступления что-то пошло не так

- **Пропали данные:** вероятно, перезапущен сервер — повторно создать смету и проверить чек.
- **Не запускается экран:** проверить адрес http://127.0.0.1:8000/health и окно терминала. Интернет после установки зависимостей не нужен.
- **Модель отправляет товар «На проверке»:** показать фактическую причину, а не подменять результат ожидаемым.
- **Нет графика:** сверить серверный расчёт через http://127.0.0.1:8000/docs и честно обозначить проблему с отображением.
- **Нужны запасные изображения:** успешный GitHub Actions сохраняет артефакт **smartruble-viewport-review**.
