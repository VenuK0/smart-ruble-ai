# Проверка устойчивости алгоритмов SmartRubleAI v0.2

**Статус:** воспроизводимый эксперимент на синтетических данных. Не оценка качества на реальных чеках, платежах или мошенничестве.

## Воспроизведение

Из корневой папки после установки requirements.txt:

Linux/macOS: PYTHONPATH=src python -m smartruble.robustness

PowerShell: $env:PYTHONPATH="src"; python -m smartruble.robustness

Команда выполняется автоматически в GitHub Actions на ветке forum-v0.2.

## Методика

- Независимые значения seed: 0–11 (12 запусков).
- Для классификатора train/test делятся по базовому типу товара, а не просто по строкам. Товары из тестового набора отсутствуют как базовые названия в обучении.
- Применяется текущий TF-IDF по символьным n-граммам + логистическая регрессия; веса внутри каждого запуска обучаются заново.
- Для антифрода при каждом запуске создаются 40 обычных и четыре искусственно аномальных продавца. Сравнивается, сколько известных заранее аномальных продавцов попали в четыре первых результата ранжирования.
- В дополнительном стресс-сценарии изменены суммы и часы операций аномальных продавцов: они становятся похожими на обычных по этим признакам. Концентрация на небольшом числе покупателей сохраняется. Таким образом, тест проверяет одну из форм сокрытия аномальных признаков, не весь спектр атак.

## Как интерпретировать

1. Утверждение «классификатор распознаёт почти все товары» не подтверждается. На новых типах результаты слабые.
2. 100% в исходном антифрод-тесте отражают способность алгоритма находить искусственно заложенные и явно различимые паттерны, а не доказательство эффективности в реальной практике.
3. Маскировка двух признаков ухудшает обнаружение на 18,75 процентного пункта (в этом эксперименте). Оценка чувствительна к заложенным сценариям.
4. Высокая модельная уверенность сама по себе не доказывает низкую частоту опасных ошибок. Перед пилотом нужны калибровка, увеличение разнообразия данных, тесты на независимых поставщиках и ручная проверка спорных случаев.

Тестировать улучшенные модели следует на тех же заранее определенных разбиениях, отдельно показывая метрики риска и долю заявок, отправленных человеку.
