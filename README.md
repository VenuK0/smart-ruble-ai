> [!IMPORTANT]
> **СмартРубль AI (SmartRubleAI) — исследовательский прототип-симуляция.** Он **не подключён** к платформе цифрового рубля Банка России, не осуществляет реальные платежи, не использует настоящие чеки и персональные финансовые данные. Все операции и ML-эксперименты моделируются. Приложение **не предназначено для публичной эксплуатации**: в нём пока нет авторизации и постоянного хранилища.

## Проблема и решение

При работе с целевыми средствами грантов и программ поддержки проверка чеков зачастую происходит уже **после покупки**. Возможные нецелевые расходы выявляются при отчётности, когда платёж уже проведён.

**Идея SmartRubleAI:** анализировать состав покупки по отдельным позициям и условиям сметы *до* условного списания целевых средств. Это **проектируемый процесс TO BE**, а не заявление о наличии банковской интеграции.

| Решение | Значение в симуляции |
|:--|:--|
| **APPROVE** | Позиция распознана как допустимая и укладывается в лимит |
| **REVIEW** | Недостаточно уверенности / категория не предусмотрена; нужен человек |
| **REJECT** | Нецелевая позиция или превышение разрешённого лимита |

Система сохраняет решения в журнале с цепочкой хэшей, отдельно позволяет исследовать аномалии в синтетических транзакциях.

## Интерфейс v0.4 — принят в основную ветку

После ручной проверки на компьютере и прохождения автотестов UI v0.4 **объединён с `main` через PR №22**. Вместо широкой левой панели используется верхняя навигация **«Средства / Контроль / Аналитика»** с двумя контекстными вкладками. Активная смета остаётся в шапке, а все шесть разделов сохранили прежние URL.

**Новый редактор смет:** выберите категорию («Расходные материалы», «Оборудование», «Литература и ПО», «Услуги») и укажите сумму обычными цифрами — например, `50000` или `1250,50`. Кнопка «Добавить статью» создаёт следующую строку; итог пересчитывается автоматически. Знак ₽ и длинное тире на клавиатуре **не нужны**. Для готовых текстов в раскрывающемся разделе «Импортировать строки» принимаются простые строки вида `Материалы - 50000` или `Оборудование: 120000`. Нераспознанные строки блокируют импорт или создание, а не пропадают незаметно.

**В «Проверке чеков»** цена и количество принимают обычную точку или десятичную запятую, в том числе `1 250,50` с пробелом. Знак ₽ вводить не нужно. Формы поиска, анализа аномалий и экономической оценки не требуют специальных символов — только текст или числа по смыслу поля.

**Чтобы открыть текущую версию из `main`:**

```powershell
git fetch origin
git switch main
git pull origin main
py -m uvicorn smartruble.api:app --app-dir src --host 127.0.0.1 --port 8000
```

Перейдите на http://127.0.0.1:8000/app и нажмите Ctrl+F5. Версия находится в `main`, но **не является публично размещённым сервисом**: запускайте только в локальной доверенной среде. Авторизация, постоянное хранилище и реальные платежи не реализованы.

Встроенный интерфейс — **рабочее место финансового контроля**: отдельные разделы, таблицы и формы, подключённые к FastAPI. Теперь стартовый экран объясняет порядок действий при пустой системе, реестр смет позволяет искать и быстро выбирать активную смету, а показатели освоения лимитов рассчитываются по данным API.

| Адрес после запуска | Возможности |
|:--|:--|
| **http://127.0.0.1:8000/app** | Главная, сметы, проверка чеков, история, антифрод, экономическая оценка |
| **http://127.0.0.1:8000/docs** | Swagger / OpenAPI с запросами и ответами |
| **http://127.0.0.1:8000/health** | Проверка состояния API |

**Экспорт для Excel:** на страницах «Сметы и лимиты» и «История операций» есть кнопки **«Экспорт CSV»**. Выгружаются отображаемые строки с учётом фильтра; разделитель — `;`, кодировка — UTF-8 c BOM. Экспорт не изменяет данные на сервере. История API ограничена последними 100 записями выбранной сметы, поэтому выгрузка не является архивом всей деятельности.

**Рекомендуемый показ для жюри:** создать пример сметы → проверить чек с целевыми и нецелевыми товарами → показать лимиты и журнал → запустить синтетический анализ аномалий → объяснить сценарный экономический расчёт. Детальный тайминг в [DEMO_RUNBOOK.md](docs/DEMO_RUNBOOK.md).

## Что умеет прототип

| Модуль | Реализовано сейчас | Ограничения |
|:--|:--|:--|
| **Разбор сметы** | Извлечение категорий и лимитов из текста по правилам | Языковая модель пока **не подключена** |
| **Классификация** | TF-IDF (символьные n-граммы) + логистическая регрессия, пороги уверенности | Обучение и тесты на синтетических наименованиях |
| **Условная проверка чеков** | Лимиты, проверки сумм, идемпотентность ID чека, ручная проверка неопределённых позиций | Нет подключения к оплате и БД |
| **Аудит** | Проверка целостности локальной цепочки SHA-256, включая временные метки | Нет внешней подписи/доверенного якоря |
| **Антифрод** | NetworkX + Isolation Forest, отдельное API-демо на синтетике | Пока **не встроен** в основной процесс оплаты |
| **Экономический сценарий** | Изменяемые допущения и расчёт эффекта/окупаемости | Не результаты пилотного внедрения |
| **Тестирование** | Проверки ядра, API, финансовых инвариантов и сценариев в GitHub Actions | Не заменяет аудит безопасности |

### Оформление

Рабочая область использует палитру **Graphite Red** и единую светлую тему. Сверху отображаются три рабочих пространства — **«Средства», «Контроль» и «Аналитика»**. В каждом доступны по две контекстные вкладки, а все разделы открываются по собственным URL `/app/...`. Навигация адаптирована для мобильных экранов без скрытого бокового меню.

Дополнительный слой **`polish.css`** согласует типографику, карточки, формы и таблицы. На телефоне поля ввода имеют удобную высоту и размер текста, широкие таблицы прокручиваются внутри панели, а навигация остаётся видимой. Добавлена печатная компоновка для документов и аналитики.

В CI выполняется браузерная проверка реальных страниц в Google Chrome на ширинах **320, 375, 768, 1280 и 1440 px** (включая заполненные данные, аналитику и меню). Для визуальной оценки GitHub Actions сохраняет изображения экранов в артефакте `smartruble-viewport-review`.

Текущий статус: **v0.4.0 — локальная исследовательская симуляция**, принятая в `main` после ручной визуальной проверки и успешных тестов. До доступного извне сервиса необходимы авторизация, безопасное хранение данных и отдельная проверка развёртывания. Реальные платежи не поддерживаются.

### Экономическая оценка

Раздел **«Экономическая оценка»** помогает изучать чувствительность гипотетического эффекта автоматизации к числу отчётов. Пользователь самостоятельно задаёт количество проверок, ручное и автоматизированное время на отчёт, стоимость рабочего часа, ежегодную эксплуатацию и разовые затраты на разработку. Серверная функция `smartruble.economics.scenario` рассчитывает **три варианта нагрузки**: 60%, 100% и 140% от заданного значения, при одинаковых остальных предположениях.

Интерфейс показывает высвобождение рабочего времени, денежный эквивалент, чистый годовой эффект, простую окупаемость, порог покрытия эксплуатации, а также **5-летнюю таблицу и график накопленного расчётного эффекта**. Для таблицы принята упрощённая формула: `год × чистый годовой эффект − разовые затраты на разработку`. Год 0 равен отрицательным разовым затратам.

**Это не измеренные результаты внедрения, не прогноз реальных денежных потоков и не подтверждённая экономия.** Не учтены инфляция, дисконтирование, налоги, риски, обучение и неизвестные затраты на интеграцию. Экономический эффект можно доказывать только после замеров на фактических процессах.

### Аналитика аномалий

Раздел **«Проверка аномалий»** запускает модель Isolation Forest на воспроизводимом **синтетическом** графе связей получателей средств и продавцов. После ввода номера набора отображаются количество операций и продавцов, **топ-10 по относительной оценке модели**, а также измеренные признаки выбранного продавца: число операций и получателей, доля крупных круглых и ночных операций, концентрация у одного получателя и средняя сумма.

**Оценка аномальности не является вероятностью мошенничества.** Длина полосы показывает только положение внутри топ-10. Для каждого продавца приведены средние значения **всех остальных продавцов** синтетического набора (не только топ-10) и понятные наблюдения по отличающимся признакам. Метки «заложен тестовый сценарий» известны из генератора данных. Сравнения не объясняют причинную работу Isolation Forest и не являются доказательством нарушений.

### История операций

Раздел **«История операций»** показывает до **100 последних записей выбранной сметы** из журнала симуляции. В таблице используются удобные номера вида `ЧЕК-0001`; это **отображаемые номера текущего журнала**, а неизменный исходный ID остаётся в деталях и CSV. Можно искать по обоим номерам, продавцу или товару, фильтровать по результату и выгружать CSV для Excel. При выборе операции подсвечивается строка и отображаются причины решений. Итоги рассчитываются по **текущей видимой выборке**.

Индикатор целостности показывает результат серверной проверки цепочки хэшей журнала. В текущем прототипе это **оперативная память**, не долговременное или неизменяемое хранение. Статус **«На проверке»** не означает, что сотрудник уже получил задачу: механизм ручного согласования пока не реализован.

### Проверка чеков

На странице **«Проверка чеков»** пользователь сначала выбирает смету, затем вводит продавца и позиции покупки. Для каждой строки видны количество, цена и предварительная сумма; общая стоимость пересчитывается при вводе. Кнопка **«Заполнить пример»** добавляет синтетический чек, а **«Очистить»** позволяет начать с пустого документа.

После проверки экран показывает сумму одобренных, направленных на ручную проверку и отклонённых позиций, а также **категорию и причину решения по каждой строке**. Результат записывается в журнал симуляции. После успешной проверки форма блокируется до нажатия **«Новый чек»**, чтобы случайное повторное нажатие не создало ещё одну операцию.

Важно: это **демонстрационная классификация**, а не настоящий платёж и не юридически значимое разрешение расхода. Сервер самостоятельно проверяет суммы, ограничения и повторное использование идентификаторов чеков; предварительные вычисления браузера не заменяют проверку сервера.

## Локальный запуск

**Требования:** Python 3.11+, доступ к PyPI при установке. Открывать приложение только локально.

~~~bash
git clone https://github.com/VenuK0/smart-ruble-ai.git
cd smart-ruble-ai

python -m venv .venv
~~~

**Windows PowerShell:**

~~~powershell
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
python -m uvicorn smartruble.api:app --app-dir src --host 127.0.0.1 --port 8000
~~~

**Linux / macOS:**

~~~bash
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
python -m uvicorn smartruble.api:app --app-dir src --host 127.0.0.1 --port 8000
~~~

После запуска откройте **http://127.0.0.1:8000/app**. Старый URL `/demo` пока работает для обратной совместимости. Первый запуск API может обучать классификатор несколько секунд. Состояние контрактов хранится **в оперативной памяти** и сбрасывается при перезапуске. Для нового демонстрационного прогона создавайте уникальный ID сметы.

<details>
<summary><b>Пример HTTP-запросов</b></summary>

Создать смету:

~~~bash
curl -X POST http://127.0.0.1:8000/contracts -H "Content-Type: application/json" \
  -d '{"grant_id":"g1","text":"Расходные материалы — 50 000 ₽\nОборудование — 120 000 ₽"}'
~~~

Проверить чек:

~~~bash
curl -X POST http://127.0.0.1:8000/contracts/g1/validate -H "Content-Type: application/json" \
  -d '{"id":"receipt-demo-1","merchant":"ООО Электроника","items":[{"name":"Микроконтроллер Arduino Uno R3","price":2500},{"name":"Шоколад Аленка молочный","price":240}]}'
~~~

Получить журнал: http://127.0.0.1:8000/contracts/g1/audit

> В Windows PowerShell удобнее использовать Swagger UI в /docs: кавычки и переносы команд curl отличаются от bash.

## Эксперименты и ограничения

Измерения выполнены **только на искусственно созданных данных**.

| Показатель | Зафиксированный результат |
|:--|--:|
| Классификация знакомых типов товаров (исходный эксперимент) | 100% |
| Классификация новых базовых типов (исходный эксперимент) | **44,88%** |
| Классификация новых базовых типов, 12 независимых seed (среднее) | **47,26%** |
| Диапазон точности на новых типах, 12 seed | **35,56–53,01%** |
| Доля искусственно заложенных аномалий в топ-4 (исходные данные) | 100% |
| То же после маскировки сумм и времени операций | **81,25%** |

**Интерпретация:** модель пока недостаточно надёжна для самостоятельного разрешения реальных покупок. Уверенность классификатора не является гарантией правильного решения; результаты антифрода нельзя переносить на настоящие случаи мошенничества. Смотрите [методику устойчивости](docs/ROBUSTNESS.md), [исходные метрики](docs/metrics.json) и [ограничения безопасности](docs/SECURITY_LIMITATIONS.md).

Экономический калькулятор показывает, при каких **предположениях** система может дать положительный эффект. Условный сценарий не является доказательством снижения затрат. Подробнее в [ECONOMIC_MODEL.md](docs/ECONOMIC_MODEL.md).

## План развития

1. **Демонстрационный прототип:** безопасность ввода, удобное демо, тестирование, воспроизводимые эксперименты.
2. **Исследовательский пилот:** больше данных, улучшение качества классификации, исследование ошибок, роли, БД и контрольный контур.
3. **Интеграционный этап:** проверка правовой и технической возможности работы с платёжной инфраструктурой, 1С и ЭДО. Наличие доступа не гарантировано.
